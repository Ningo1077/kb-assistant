## 二、填写稿：作业要求栏（表格第三列）

> 本项目采用前后端分离架构。**编程语言核对：1. HTML/CSS/JavaScript（TypeScript）；2. Python；3. Rust；另使用 SQL 操作数据库。**
>
> **前端（网页端）**：React 18 + TypeScript + Vite 单页应用，不引入组件库、UI 全手写，通过 SSE 接收服务端推送实现逐字流式渲染。
>
> **桌面客户端**：Tauri 2.x（Rust 内核），复用同一套 React 界面代码，打包为 Windows `.exe` 安装包，具备系统托盘常驻、全局快捷键（Ctrl+Shift+Space）唤起、本地文件拖拽直读入库三项网页端不具备的系统能力。
>
> **后端**：Python 3.11 + FastAPI + SQLAlchemy 2.0 + Pydantic v2，提供 RESTful API 与 SSE 流式接口，含 JWT 无状态鉴权、PBKDF2-SHA256 口令散列、文档解析—清洗—分块—向量化入库管线、向量与关键词双路混合检索。
>
> **数据库**：PostgreSQL 16/17 + pgvector 扩展，7 张表（users、knowledge_bases、documents、chunks、conversations、messages、feedbacks），`chunks` 建 HNSW 向量索引与 GIN trigram 索引。
>
> **辅助**：Ollama 本地部署 qwen2.5，完成向量化与答案生成。
>
> **部署**：全部组件本地运行，文档不出本机，断网可用。

## 三、填写稿：项目需求分析、功能描述栏（表格第四列）

**需求分析**

课程资料、项目文档与个人笔记分散在大量 PDF / Word / Markdown 文件中，存在三个问题：一是文件名不含内容关键词，"某个参数在哪份文档里说过"只能逐个打开翻找；二是个人笔记、小组未公开的作业不适合上传到公有云问答服务，存在隐私与版权顾虑；三是直接问通用大模型会编造答案，无法核对出处。

为解决"检索难、不敢上传、答案不可信"三点，本系统采用 React + FastAPI 前后端分离开发，以 PostgreSQL + pgvector 在同一数据库内完成"按知识库过滤 + 向量近邻排序"，答案强制标注来源文件名与页码，并封装为 Tauri 桌面客户端，实现文档不出本机的私有化知识库问答。

**功能描述**

1. 注册登录：邮箱 + 密码注册登录，JWT 会话保持，接口全鉴权。
2. 知识库管理：创建 / 删除 / 列表，按知识库隔离文档与检索范围。
3. 文档上传入库：支持 PDF / DOCX / MD / TXT，解析 → 清洗 → 分块 → 向量化 → 落库，入库状态实时可见；相同内容（sha256 一致）的文件复用已有分块，不重复入库。
4. 智能问答：自然语言提问，答案流式逐字输出。
5. 引用溯源：每条答案标注来源文件名与页码，点击可查看原文片段。
6. 会话历史：多轮对话自动保存，刷新不丢失。
7. 混合检索：向量语义召回与关键词召回双路并行，RRF 算法融合排序。
8. 拒答机制：知识库中无依据时明确回答"资料中未提及"，抑制大模型幻觉。
9. 回答反馈：对单条回答点赞 / 点踩留痕。
10. 失败可见：解析失败（如扫描件 PDF）给出明确原因，支持一键重新索引。

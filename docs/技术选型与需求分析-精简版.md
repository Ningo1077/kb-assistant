# 私有文档知识库问答助手 —— 技术选型、需求分析与功能描述

> 项目立项 / 技术方案评审用。实现与本文一致，接口与表结构可在后端仓库核对。

## 一、技术选型

### 1.1 架构

前后端分离的 B/S + C/S 混合形态，四层：

```
表现层：Tauri 桌面端（Rust） + 网页端（React/TypeScript）
服务层：Python 3.11 + FastAPI（认证、文档管线、检索、问答编排）
数据层：PostgreSQL 16/17 + pgvector
辅助层：Ollama 本地部署 qwen2.5
```

层间通信：HTTP(REST) + SSE。

### 1.2 编程语言（要求：两种以上）

实际 **4 种**：

| 语言 | 用在哪里 | 职责 |
|---|---|---|
| HTML/CSS/JS（TypeScript） | 网页端、桌面端界面 | 页面结构、样式、全部交互逻辑 |
| Python | 后端服务 | 解析、分块、向量化、检索、调模型、REST/SSE 接口 |
| Rust | 桌面客户端外壳 | 窗口、托盘、全局快捷键、本地文件读取 |
| SQL | 数据库 | 建表、索引（含 HNSW）、关联查询、事务 |

选型依据：TS 静态类型保证前后端接口契约；Python 的 AI/文本生态最成熟、FastAPI 按类型注解自动出文档；Rust 使 Tauri 打包体积 150MB → 5MB；SQL 让关系查询与向量检索同库完成。

### 1.3 前端

**React 18 + TypeScript + Vite**，不用组件库、UI 手写。理由：单向数据流契合"消息流式追加"的高频更新；Vite 冷启动秒级、产物小；SSE 逐字上屏是核心交互，也是与普通 CRUD 页面拉开差距之处。

### 1.4 后端

**FastAPI + SQLAlchemy 2.0 + Pydantic v2**。异步 ASGI 原生支持 `StreamingResponse`，SSE 只需一个生成器；自动生成 Swagger，全部接口可浏览器调试；Pydantic 在业务前完成出入参校验；密码 PBKDF2-SHA256（26 万次迭代 + 随机盐），会话用 JWT。

### 1.5 数据库（要求：数据库）

**PostgreSQL 16/17 + pgvector**，7 张表：users、knowledge_bases、documents、chunks、conversations、messages、feedbacks。

| 候选 | 结论 | 理由 |
|---|---|---|
| **PostgreSQL + pgvector** | ✅ 选用 | 关系与向量同库，一条 SQL 完成"知识库过滤 + 向量近邻排序"，沿用 PG 事务、备份、迁移能力 |
| MySQL | ✗ | 8.0 无原生向量类型，需外挂 ES 或 Milvus |
| SQLite | △ | 零安装宜开发，并发写与向量索引弱，仅作回退方言 |
| Milvus / Chroma | △ | 十万级以下数据部署成本大于收益 |

关键点：`vector(512)` + HNSW 索引（O(N) → O(logN)）；文本列 GIN trigram 支撑关键词召回；`documents` 对 `(kb_id, sha256)` 唯一约束实现秒传；经方言抽象改一行连接串即可切 SQLite。

### 1.6 作品形态（要求：前后端形态；客户端 +5）

网页端 + 桌面客户端双形态，复用同一套 React 代码：

| 形态 | 技术 | 说明 |
|---|---|---|
| 网页端 | React + Vite，浏览器访问 | 主要开发调试形态 |
| 桌面客户端 | Tauri 2.x（Rust 内核），`.exe` 安装包 | 托盘常驻、Ctrl+Shift+Space 唤起、本地文件拖拽直读入库、免浏览器 |

客户端非"套壳"：具备网页端没有的托盘、快捷键、本地文件直读三项系统能力，可现场安装演示。

## 二、需求分析

### 2.1 背景与痛点

课件、项目文档、个人笔记散落在大量 PDF/Word/Markdown 中，三个痛点：

1. **检索难**——文件名不含内容关键词，只能逐个打开翻找；
2. **不敢上传**——个人笔记与未公开材料不适合放公有云问答；
3. **答案不可信**——通用大模型会编造，无法核对出处。

### 2.2 目标用户

| 用户 | 场景 |
|---|---|
| 学生个人 | 导入一学期课件，考前自然语言提问复习 |
| 小组 / 实验室 | 共享规范文档库，新成员提问即上手 |
| 资料在手边的场景 | 文档不出本机，断网可用 |

### 2.3 功能需求

**核心（P0）**

| 编号 | 需求 | 描述 |
|---|---|---|
| F1 | 注册登录 | 邮箱 + 密码注册，JWT 会话，接口鉴权 |
| F2 | 知识库管理 | 创建 / 删除 / 列表，按知识库隔离文档与检索范围 |
| F3 | 文档上传入库 | PDF/DOCX/MD/TXT：解析 → 清洗 → 分块 → 向量化 → 落库，状态实时可见 |
| F4 | 智能问答 | 自然语言提问，流式输出 |
| F5 | 引用溯源 | 标注来源文件名与页码，点击查看原文 |
| F6 | 会话历史 | 多轮对话自动保存，刷新不丢 |

**增强（P1）**

| 编号 | 需求 | 描述 |
|---|---|---|
| F7 | 秒传去重 | sha256 相同复用已分块，不重复入库 |
| F8 | 混合检索 | 向量 + 关键词双路召回，RRF 融合 |
| F9 | 拒答机制 | 无依据时答"资料中未提及"，抑制幻觉 |
| F10 | 质量反馈 | 单条回答点赞 / 点踩留痕 |
| F11 | 失败可见 | 解析失败给出原因，可一键重新索引 |

### 2.4 非功能需求

| 维度 | 要求 |
|---|---|
| 安全 | 密码不可逆存储；接口全鉴权；越权返回 404 |
| 性能 | 流式首字 < 2s；向量检索毫秒级；embedding 16 条/批 |
| 可用性 | 入库各阶段状态可视化；失败给可读原因 |
| 可移植 | 全本地、断网可用；改连接串即可上云 |
| 可验证 | 全部接口有 Swagger；提供端到端测试脚本 |

## 三、功能描述

### 3.1 模块划分

```
前端（React/TS）            后端（FastAPI/Python）
├── 登录注册                ├── 认证（JWT 签发/校验）
├── 知识库侧边栏            ├── 知识库（CRUD + 归属校验）
├── 文档面板                ├── 文档（上传/列表/重索引/删除）
│   ├── 拖拽上传            ├── 入库管线（解析→清洗→分块→向量化）
│   └── 状态与进度          ├── 检索（双路召回 + RRF 融合）
└── 聊天面板                └── 问答（Prompt 组装 + SSE 流式生成）
    ├── 流式逐字渲染
    ├── 引用角标与来源
    └── 历史会话
```

### 3.2 核心流程

**入库（离线，一次性）**

1. 算 SHA256 与库内比对，命中即复用（秒传）；
2. 按类型解析带页码文本（PDF 逐页、DOCX 含表格、MD/TXT 整体）；
3. 清洗：删页码/页脚、合并被硬换行切断的句子、保护标题与列表结构；
4. 按段落与句边界分块（~800 字符，重叠 120），分批向量化写入 `chunks`；
5. 状态 `parsing → embedding → ready`，失败转 `failed` 并记原因。

**问答（在线，每次对话）**

1. 问题向量化，双路检索：向量 Top 20 + 关键词 Top 20；
2. RRF（k=60）融合取前 5 片段；
3. 片段（编号/文件名/页码）+ 最近 3 轮历史组装受约束 Prompt：仅依片段作答、必须标 `[n]`、无依据须拒答、温度 0.1；
4. Ollama 流式生成，SSE 推送前端；
5. `[n]` 渲染成可点击角标；回答与引用写入 `messages`。

### 3.3 数据库设计要点

| 表 | 关键设计 |
|---|---|
| `chunks` | `embedding vector(512)` + HNSW 余弦索引；`page_no` 支撑溯源 |
| `documents` | `(kb_id, sha256)` 唯一约束实现秒传；`status` 状态机驱动进度 |
| `messages` | `citations JSONB` 存引用快照，回看历史无需重检索 |
| 其余 | `users`（PBKDF2）、`knowledge_bases`（归属隔离）、`conversations`、`feedbacks` |

### 3.4 接口（14 个，均有 Swagger）

- 认证：`POST /api/auth/register`、`POST /api/auth/login`、`GET /api/auth/me`
- 知识库：`GET|POST /api/kbs`、`GET|DELETE /api/kbs/{id}`
- 文档：`GET|POST /api/kbs/{id}/documents`、`POST .../{doc_id}/reindex`、`DELETE .../{doc_id}`
- 问答：`POST /api/chat`（SSE）、`GET /api/chat/conversations`、`GET .../messages`、`DELETE /api/chat/conversations/{id}`、`POST /api/chat/feedback`

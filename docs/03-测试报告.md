## 一、测试目的与范围

验证「需求分析 → 设计 → 编码」各阶段承诺的功能与非功能要求是否真实落地，重点覆盖：

1. **功能**：注册登录、知识库 CRUD、文档入库（解析/清洗/分块/向量化/状态机）、秒传去重、混合检索、SSE 流式问答、引用溯源、会话历史、回答反馈、重新索引；
2. **安全**：口令散列、JWT 鉴权、跨用户/跨知识库越权、入参校验；
3. **非功能**：流式响应完整性与延迟、构建可复现性、测试环境隔离；
4. **回归**：在真实本地模型（Ollama）配置下再跑一次完整链路，确认离线模拟配置与真实模型配置都能工作。

**不在本次范围内**：PostgreSQL + pgvector 生产库实测（本机仅有 SQLite 与 Ollama，PG 路径通过方言抽象与设计评审覆盖，部署手册给出验收步骤）；Tauri 安装包的安装/卸载人工验收（属人工测试，见 `docs/04-部署手册.md` 的验收清单）；大规模并发压测（定位为本机单机使用）。

## 三、测试策略与分层

```
第 4 层  构建验证        tsc --noEmit && vite build（类型 + 产物）
第 3 层  端到端冒烟      注册→登录→建库→上传→入库→检索→流式问答→引用落库
第 2 层  接口/安全测试    TestClient 打真实路由，含正向与负向用例
第 1 层  单元测试        文本清洗/分块、向量化、RRF 融合、Prompt、口令/JWT
```

- 正向用例验证「该做的做了」，负向用例验证「不该做的被挡住且状态码正确」；
- 每条用例独立生成随机邮箱，避免用例间耦合与顺序依赖；
- 断言尽量落在**契约**（状态码、字段名、事件类型、落库条数）而非实现细节，重构时不易误报。

## 六、缺陷记录

| 编号 | 严重度 | 现象 | 根因 | 处理 | 验证 |
|---|---|---|---|---|---|
| DEF-01 | 中 | 清洗后仍残留「第 3 页 / 共 20 页」页脚，污染向量 | `_PAGE_LABEL` 正则只容纳一个 `/`／`共` 字符，无法匹配「/ 共 20 页」组合 | 已修复 `backend/app/services/text.py`：支持「第 N 页」「第 N 页 / 共 M 页」「N / M 页」等形态 | TC-TXT-02 通过 |
| DEF-02 | 中 | 关键词召回通道命中不稳定，同一问题跨进程结果不同 | `_terms` 用 `set` + 等长 bigram 按长度排序后截断前 6 个，顺序随哈希种子变化 | 已修复 `backend/app/services/retrieval.py`：改为按出现顺序去重保序、拉丁型号词优先，结果跨进程可复现 | TC-EMB-04/05 通过 |

**观察项（非阻断，建议后续处理）**

| 编号 | 说明 | 建议 |
|---|---|---|
| OBS-01 | 需求 F11 声称「可一键重新索引」，后端 `POST /reindex` 已实现并有 TC-API-16 覆盖，但 `frontend/src/components/DocPanel.tsx` 只有「删除」按钮，UI 未提供入口 | 在 `failed` 状态行增加「重新索引」按钮，调用 `api.reindex()`；或修订需求措辞为「接口支持重新索引」 |
| OBS-02 | 非功能指标「流式首字延迟 < 2s」在 `mock` 模式满足（TC-API-12，<2s 断言通过），但真实 Ollama 3B 端到端耗时 **11.6s**（证据 04） | 该指标应按 provider 区分表述；真实模型可改用更小模型、量化版本或将「首字延迟」与「完整生成耗时」分开计量 |
| OBS-03 | 部分既有文档口径不一致：编程语言数（README/需求分析写 4 种，作业对照稿写 3 种 + SQL）、全局快捷键（需求分析写 `Ctrl+Shift+Space`，代码实现与 README 为 `Ctrl+Shift+K`）、接口数量（写 14 个，实为 17 个业务端点 + `/health`） | 详见 `docs/00-交付物清单与全过程索引.md` 第七节，提交前统一口径 |
| OBS-04 | `StarletteDeprecationWarning`（`httpx` 与 `starlette.testclient` 搭配）出现在所有测试日志中 | 仅影响日志观感，不影响结果；后续按 FastAPI 升级指引迁移 `httpx2` |

1. 需求 F1~F10 及 F11 的后端部分均有自动化用例覆盖并全部通过；DEF-01、DEF-02 两个真实缺陷已定位、修复并回归验证；

5. **结论：本项目当前版本具备交付/现场演示条件**。遗留 OBS-01~04 均为非阻断项，其中 OBS-03 建议在提交前统一文档口径。

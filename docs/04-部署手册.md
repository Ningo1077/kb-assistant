# 部署手册 · 私有文档知识库问答助手

> 适用：现场部署、换机演示、从源码复现、从开发配置切到真实模型
> 配套：`README.md`（快速开始）、`backend/README.md`（模型切换）、`docs/05-使用说明书.md`（面向使用者）

---

## 一、部署形态与选择

| 形态 | 场景 | 前置依赖 | 预计步骤 |
|---|---|---|---|
| **A 源码开发/零依赖** | clone 后第一次跑通、CI、无模型机器 | Python 3.11+、Node 18+ | §4，5 条命令 |
| **B 本机真实问答** | 现场演示真实 RAG 效果 | A + Ollama（可选 PostgreSQL） | §5，含模型拉取与重建索引 |
| **C 桌面安装包** | 交付/演示机免装 Python、Node | 打包机需 Rust + MSVC；**目标机只需 WebView2** | §6，含打包与安装验收 |
| **D 前端静态托管** | 局域网内多人访问（可选） | B + Nginx/任意静态服务器 | §5.4 |

> 三种形态共用同一套后端代码，差异只在 `.env` 与前端载体。**不要把开发机的 `.env` 和 `app.db` 拷给别人**：安装包已用白名单隔离（§6.4）。

## 二、环境要求（已在下列版本验证）

| 组件 | 版本 | 备注 |
|---|---|---|
| 操作系统 | Windows 10/11（主要验证平台） | 后端与前端代码跨平台；Tauri 安装包为 Windows x64 |
| Python | 3.14.6 验证通过（要求 ≥3.11） | `backend/.venv` |
| Node.js / npm | v22.22.2 / 10.9.7（要求 Node ≥18） | `frontend/node_modules` |
| Rust + MSVC | 仅**桌面端打包**需要 | 仅运行 Web 端或安装已构建安装包不需要 |
| 数据库 | SQLite（零安装，默认）／ PostgreSQL 16/17 + pgvector | 二选一 |
| 模型服务 | Ollama（可选）`bge-m3` + `qwen2.5:3b` | 不装则用 `hashing` + `mock` |
| WebView2 | 桌面端运行需 | Windows 11 一般内置，安装包自带引导检测 |

依赖锁定：`backend/requirements.txt`、`frontend/package-lock.json`、`src-tauri/Cargo.lock`。

## 三、配置参考（`backend/.env`）

从 `.env.example` 复制，不要提交真实 `.env`（已在 `.gitignore` 中）。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./data/app.db` | 改 `postgresql+psycopg://user:pwd@host:5432/kb_assistant` 即切 PG |
| `JWT_SECRET` | 空 | **留空最安全**：首次启动自动生成本机随机密钥写入 `data/secret.key`；多实例部署必须显式填同一个长随机串 |
| `JWT_EXPIRE_MINUTES` | `10080` | token 有效期（7 天） |
| `CORS_ORIGINS` | Vite + Tauri 本机来源 | 逗号分隔；**不要填 `*`** |
| `EMBED_PROVIDER` | `hashing` | `hashing` / `ollama` / `openai` |
| `EMBED_DIM` | `512` | **换 provider 必须同步改**：`bge-m3` 为 `1024` |
| `EMBED_MODEL` | `bge-m3` | |
| `LLM_PROVIDER` | `mock` | `mock` / `ollama` / `openai` |
| `LLM_MODEL` | `qwen2.5:7b` | 16GB 内存机器建议 `qwen2.5:3b` |
| `LLM_BASE_URL` | `http://localhost:11434` | Ollama 或任意 OpenAI 兼容 `/v1` 地址 |
| `LLM_API_KEY` | 空 | 本地服务一般不校验，随便填 |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `800` / `120` | 分块参数 |
| `RETRIEVE_TOP_K` / `RETRIEVE_RECALL_K` | `5` / `20` | 融合后取前 5、双路各召回 20 |
| `MAX_CONTEXT_CHARS` | `6000` | 送入模型的片段总预算 |

> 桌面端可执行文件另支持 `KB_BACKEND_DIR`（指定后端目录）与 `KB_BACKEND_PORT`（默认 8000）。
> `settings` 与 `get_embedder` 都有 `lru_cache`：**改完 `.env` 必须重启后端**才生效。

## 四、形态 A：源码开发 / 零依赖部署

```bash
# 1) 后端（在 backend/ 目录）
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt   # macOS/Linux: .venv/bin/python
cp .env.example .env                                          # Windows: Copy-Item .env.example .env
.venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8000

# 2) 前端（另开终端，在 frontend/ 目录）
npm ci
npm run dev                                                   # http://localhost:5173
```

验收：

| 检查 | 命令 / 地址 | 期望 |
|---|---|---|
| 健康检查 | `curl http://127.0.0.1:8000/health` | `{"status":"ok","database":"sqlite","embed_provider":"hashing","llm_provider":"mock"}` |
| 接口文档 | `http://127.0.0.1:8000/docs` | Swagger 列出 17 个业务端点 |
| 前端 | `http://localhost:5173` | 出现登录卡片 |
| 端到端 | `.venv/Scripts/python.exe scripts/smoke_test.py` | `全链路通过…` |
| 自动化测试 | `.venv/Scripts/python.exe -m unittest discover -s tests -p "test_*.py" -v` | `Ran 39 tests ... OK` |

首次启动会在 `backend/data/secret.key` 生成随机 JWT 密钥（不入库）。该密钥变更会让旧 token 失效，重新登录即可。

## 五、形态 B：本机真实问答（PostgreSQL + Ollama）

### 5.1 模型准备

```bash
# 建议先把模型放到非系统盘
set OLLAMA_MODELS=D:\models        # PowerShell: $env:OLLAMA_MODELS="D:\models"
ollama serve
ollama pull qwen2.5:3b
ollama pull bge-m3
```

> Windows 若以服务方式启动 Ollama，服务进程不继承当前 shell 的环境变量，需写启动脚本显式设置 `OLLAMA_MODELS` 后重启服务。

### 5.2 数据库（可选，跳过则用 SQLite）

```sql
CREATE DATABASE kb_assistant;
CREATE EXTENSION vector;
CREATE EXTENSION pg_trgm;
```

`.env` 改为：

```env
DATABASE_URL=postgresql+psycopg://postgres:你的密码@localhost:5432/kb_assistant
```

启动时 `init_db()` 自动建表并创建 `idx_chunks_embedding_hnsw`（HNSW 余弦）与 `idx_chunks_content_trgm`（GIN trigram）。

### 5.3 切换到真实模型（顺序不能错）

```env
EMBED_PROVIDER=ollama
EMBED_MODEL=bge-m3
EMBED_DIM=1024            # 必须与 bge-m3 维度一致
LLM_PROVIDER=ollama
LLM_MODEL=qwen2.5:3b
LLM_BASE_URL=http://127.0.0.1:11434
```

1. **改两份配置**：开发版 `backend/.env` 与桌面端已安装版 `<安装目录>/backend/.env`；
2. **重启后端**（`lru_cache` 缓存）；
3. **重建全部索引**：`.venv/Scripts/python.exe scripts/reindex_all.py`（重建已安装版时把它的 backend 目录作为参数传入）；
   > 512 维哈希向量与 1024 维语义向量混用会让检索直接报形状不匹配，这一步不能省；
4. 验证：`/api/chat` 的回答不再含「离线模拟回答」。

换成 DeepSeek 等云端模型或 LM Studio / llama.cpp / vLLM 时，把 `LLM_PROVIDER` / `EMBED_PROVIDER` 设为 `openai`，`LLM_BASE_URL` 指向对应 `/v1`。

### 5.4 前端静态托管（可选）

```bash
cd frontend && npm run build      # 产出 frontend/dist/
```

用 Nginx 托管 `dist/`，并把后端 API 反代到 `:8000`；同时把 `CORS_ORIGINS` 改成实际前端地址。

```nginx
server {
  listen 8080;
  root  /path/to/kb-assistant/frontend/dist;
  index index.html;
  location / { try_files $uri $uri/ /index.html; }
  location /api/ { proxy_pass http://127.0.0.1:8000/api/;
                   proxy_buffering off;          # SSE 必须关闭缓冲
                   proxy_read_timeout 300s; }
  location /health { proxy_pass http://127.0.0.1:8000/health; }
}
```

> `proxy_buffering off` 是流式回答能否逐字上屏的关键；若未关闭，回答会等全部生成完才一次性到达。

## 六、形态 C：Tauri 桌面安装包

### 6.1 打包前准备

```bash
backend\scripts\prepare-backend.bat      # 创建/安装供安装包内置的 .venv
```

在**项目根目录 `kb-assistant/`** 执行（tauri CLI 在其它目录找不到 `tauri.conf.json`）：

```bash
frontend/node_modules/.bin/tauri build
```

产物：`src-tauri/target/release/bundle/nsis/KB-Assistant_<VERSION>_x64-setup.exe`。

发版时**同步更新两处版本号**：`src-tauri/tauri.conf.json` 的 `version` 与 `src-tauri/nsis/setup.nsi` 的 `!define VERSION`。

**兜底方案**：打包机没有 MSVC 链接器时，可复用已编译 exe 与缓存的 NSIS 工具链重打安装包 —— `src-tauri/nsis/build-setup.cmd`。该方案产物不含 WebView2 引导检测，正式交付优先用标准 `tauri build`。

### 6.2 安装与运行

1. 双击 `.exe`，按向导安装（首次自动检测 WebView2）；
2. 启动后 Tauri 后台线程拉起内置 venv 的 uvicorn，探测 `127.0.0.1:8000` 就绪后显示窗口；若已有 Web 端后端在跑则直接复用；
3. 空库由 `backend/scripts/make_seed_db.py` 生成（7 张表、0 行数据），首次启动自动建表；
4. 首次使用注册一个本地账号即可开始上传文档。

> 安装包内置 `.venv` 的 `pyvenv.cfg` 指向**打包机**的 Python 路径。目标机若无该版本 Python，运行 `backend\scripts\prepare-backend.bat` 重建 venv 即可。

### 6.3 卸载

入口：Windows「设置 → 应用 → 已安装的应用」、开始菜单 `Uninstall KB-Assistant`、安装目录下 `uninstall.exe`（静默 `/S`）。

- `src-tauri/windows/uninstall-cleanup.ps1`：按安装路径 + `app.main:app` 精确结束本应用拉起的后端 python（不误杀其它 Python 进程），并按需把 `backend/data` 备份到 `文档\KB-Assistant-Backup\<时间戳>`；备份根目录可用 `KB_BACKUP_ROOT` 覆盖；
- `src-tauri/windows/hooks.nsh`：标准 NSIS 卸载钩子，交互卸载询问是否保留数据，**静默卸载默认保留数据**；
- `src-tauri/nsis/setup.nsi` + `build-setup.cmd`：独立安装/卸载兜底脚本。

### 6.4 打包数据隔离（交付前必查）

`tauri.conf.json` 的 `resources` 与 `setup.nsi` 都使用**显式白名单**，只包含：

```
backend/app/ · backend/scripts/ · backend/requirements.txt
backend/.env.example · backend/.venv/ · windows/uninstall-cleanup.ps1
```

**绝不打包**：`backend/.env`、`backend/data/app.db`、`backend/data/uploads/`、`*.bak`、`secret.key`、`backup-installed-data/`。交付前建议用压缩软件打开安装包核对一次。

## 七、数据备份、恢复、升级与回滚

| 操作 | 做法 |
|---|---|
| 备份（SQLite） | 停服务 → 复制 `backend/data/app.db` 与 `backend/data/uploads/` 到安全位置 |
| 恢复（SQLite） | 停服务 → 把备份放回原路径 → 启动 → `/health` 与文档列表核对 |
| 备份（PG） | `pg_dump -Fc kb_assistant > kb.dump`；恢复用 `pg_restore` |
| 升级代码 | `git pull` → 重启后端 → 跑 `smoke_test.py` 与 39 个自动化用例 |
| 升级 embedding 模型 | 改 `EMBED_DIM` → 重启 → `scripts/reindex_all.py` → 抽 3 个问题核对引用命中 |
| 回滚 | 恢复上一版代码 + 上一版数据库备份；若向量维度已变，**必须同时回滚数据库**，否则检索形状不匹配 |
| 换机演示 | 优先用形态 C 安装包（自带 venv 与空库）；只拷 `demo-files/` 作演示文档，不拷开发库 |

## 九、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 前端报跨域 / 接口 404 | 后端没起、端口不对、CORS 未包含前端地址 | 查 `/health`；把前端地址加进 `CORS_ORIGINS` 并重启 |
| 登录后立刻掉登录 | 多进程各自生成了随机密钥 | 在 `.env` 显式配置同一个 `JWT_SECRET` |
| 上传后卡在「解析中」 | 后台任务异常或模型不可用 | 看后端日志与文档 `error_msg`；失败后可调用 `POST /reindex` |
| 扫描件 PDF 入库失败 | 无可提取文本 | 属预期行为，需 OCR 预处理；界面会显示具体原因 |
| 切 Ollama 后检索报形状不匹配 | 512 维旧向量与 1024 维新向量混用 | 改 `EMBED_DIM=1024` → 重启 → `scripts/reindex_all.py` |
| 改 `.env` 不生效 | `lru_cache` | 重启后端 |
| 回答不流式、一次性出现 | 反代开了缓冲 | Nginx 加 `proxy_buffering off;` |
| 回答全是「离线模拟回答」 | `LLM_PROVIDER=mock` | 改为 `ollama` 并确认 Ollama 已启动、模型已 pull |
| 桌面端白屏 | 后端未就绪 / WebView2 缺失 | 手动起 `uvicorn app.main:app --port 8000` 后重开；安装 WebView2 |
| 安装包在别的机器起不来 | 内置 venv 指向打包机 Python | 目标机运行 `prepare-backend.bat` 重建 venv |
| 卸载后数据没了 | 交互卸载选了「不保留」 | 到 `文档\KB-Assistant-Backup\` 找时间戳备份恢复 |
| 测试日志有 `StarletteDeprecationWarning` | `httpx` 与 `starlette.testclient` 搭配的告警 | 不影响结果，按 FastAPI 升级指引迁移即可 |

## 十、安全加固（若暴露到局域网/公网）

项目默认定位为本机 / 局域网单机使用。若要公网部署，必须补充：

1. TLS 终止（HTTPS），SSE 连接同样走加密通道；
2. 速率限制与注册管控（当前注册接口无邀请码/验证码）；
3. 上传内容扫描与文件大小/类型二次校验；
4. 显式长随机 `JWT_SECRET`、缩短 token 有效期；
5. `CORS_ORIGINS` 白名单收紧，禁止 `*`，并关闭 Swagger 或加鉴权；
6. 数据库备份加密与访问审计。

## 十一、CI/CD

`.github/workflows/ci.yml` 在 push `main/master`、PR 或手动触发时自动执行：

```yaml
backend: 安装依赖 → 39 个单元/接口用例 → 冒烟测试 → 空白种子库生成校验
frontend: npm ci → tsc --noEmit && vite build
```

本地交付前建议按第八节清单跑一遍，避免 CI 红灯。
